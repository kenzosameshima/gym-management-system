# v1.0.0 Release Notes

Status: Unreleased release candidate.

## Summary

`v1.0.0` prepares Gym Management System as a stable MVP. The release focuses on final integration review, release-blocking fixes, documentation accuracy, environment clarity, Docker readiness, validation, and honest limitation tracking.

## Main Capabilities

- JWT authentication with role-based authorization.
- Student, plan, enrollment, payment, and access-control operations.
- Workout plans, exercises, and exercise progress history.
- Reports for active students, defaulters, plan usage, revenue, daily access, and workout summary.
- Role-aware dashboard with operational charts.
- Dockerized PostgreSQL, backend, production frontend, and Vite development frontend.

## Architecture Highlights

- FastAPI async backend with API, service, repository, and database layers.
- PostgreSQL persistence through SQLAlchemy async and Alembic migrations.
- React/Vite frontend with protected routes, typed API modules, and shared operational components.
- Backend authorization remains authoritative; frontend role navigation is a usability layer.

## Security Notes

- Production requires a unique `SECRET_KEY`, `DEBUG=false`, and explicit CORS origins.
- Password hashes are never exposed in API responses.
- Request logs must not include passwords or bearer tokens.
- The MVP stores JWTs in `localStorage`; refresh tokens are not implemented.
- Vite/esbuild development-server advisory remains documented. Production serves built static assets through Nginx.

## Known Limitations

- No payment gateway integration.
- No refresh tokens.
- No email notifications.
- No CSV/PDF exports.
- No hardware/catraca integration.
- No mobile app.
- Some relationship selection remains ID-based.
- Dashboard charts are operational summaries, not advanced analytics.
